## 住宅 IP 和机房 IP 差在哪，“住宅”三个字为什么不够

住宅 IP 由 ISP 分配给真实家庭宽带用户，比如美国的 AT&T、Comcast。通过这类地址访问 Instagram，平台看到的网络特征和本地用户在家刷手机没有区别。

机房 IP 走的是商业 ASN 网段。主流平台的反欺诈系统都维护着数据中心 ASN 名单，这类地址在 IP 查询工具里常直接显示为 hosting network，也就是托管网络。名单里的地址段，账号再老也照样被限制。

但“住宅 IP”这个标签本身不保证安全。代理池里被反复转售的住宅地址，信誉同样会被拉低。平台判断一条 IP 好不好用，看的是它有没有被大量账号共用过、历史操作记录干不干净、归属地和账号定位是否一致。纯净度、真实性、使用历史这三项，比“住宅”两个字重要得多。

这里有个反直觉的现象值得单独说：移动 IP 常被当成最干净的选择，实际未必。运营商级 NAT（CGNAT，RFC 6269 有描述）会让大量真实用户共用一个公网 IP，平台封掉一个移动出口，可能连带一片真实用户。SixtyNet 的住宅线从产品路径看指向 AT&T Mobility 这类移动运营商网络，如果你打算用它跑高价值账号，先小号试一段时间，确认这条 IP 在 Instagram 上的实际表现，再决定要不要把主号迁过去。

## 静态还是动态：两种做法，各有各的场景

静态 ISP 的特点是套餐周期内 IP 固定不变。今天用这个地址，一个月后还是它。Instagram 对账号的网络环境一致性很敏感，出口地址来回变，哪怕每次都是住宅地址，也会被注意到，触发“网络环境异常”之类的验证。

动态住宅代理每次连接可能换一个地址，适合需要模拟不同地区用户、批量浏览或注册的场景。代价是账号环境频繁变动，长期养的主号放上去并不合适。

几家服务商给出的方案并不一致：

- LoongProxy 在 2026 年 9 月的文章里主张核心品牌账号用静态、纯净、归属地匹配的原生住宅 IP，一个 IP 对一个账号，多账号矩阵按“账号—固定 IP”一一绑定。
- IPIPGO 的方案是“静态打底 + 动态模拟”：新号前 3 天用静态住宅 IP 培养设备指纹，发帖期切动态 IP 模拟真人移动轨迹，互动高峰再用城市级定位 IP 匹配用户时区。
- kookeey 主推动态轮换，断线时自动换到同定位的新 IP，另外提供 30 天独享的静态 IP 作为补充。

按场景归纳：有粉丝基础、能带来收入的主账号，用静态，别折腾；批量小号、需要测试不同地区表现，可以用动态，但切换频率别高到像在跑脚本。两种做法都不是平台规则，是运营经验。

能落地的判断方式是按账号价值分档：能直接带来收入的号、投过广告的号，一条 IP 只挂它一个，出问题的成本远高于多买一条 IP；测试号、素材号可以两三个共用一条，但要接受它们互相牵连的风险。LoongProxy 的 FAQ 里也承认，同一个 IP 登录太多账号，或者短时间大量互动，用了住宅 IP 照样触发验证。

## 带宽、延迟、流量：被忽略的第三个变量

选 IP 时大家盯着类型和纯净度，带宽往往最后才看，但它直接决定日常操作顺不顺手。

- LoongProxy 的带宽上限是 10Mbps，欧美节点响应时间在 1000ms 以内，东南亚节点在 500ms 以内。
- VIRCS 的 VPS 套餐从 50Mbps 独享起步，专线隧道给到 300Mbps；第三方测评称 50Mbps 套餐实测均值 46.2Mbps，中国访问平均 ping 195ms，高峰丢包低于 0.3%。
- SixtyNet 的住宅套餐在官网标的是 2G / 4G / 10G Premium Network，流量 5TB 到 40TB。

10Mbps 和 50Mbps 的差别，发几条图文感受不出来。上传一组高清素材、在远程桌面里拖时间线、同时开五个浏览器实例，差距立刻显现。延迟影响的是操作手感，不直接决定账号安不安全，但延迟高到每次点击都等半秒，运营效率会明显下降。

流量额度也要算。Instagram 图文本身消耗不大，可如果你在服务器里跑自动浏览、批量下载竞品内容做素材，几十 GB 很快就没了。SixtyNet 最低档 5TB、最高 40TB 的额度，对纯账号运营是绰绰有余的量级。
